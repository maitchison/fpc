Free Pascal IDE / Compiler -- changelog
=======================================

Most recent version first. The IDE shows this file from
Help | What's new...


== IDE 1.0.24 / Compiler 3.4.0 ==

  * Cross-unit asm-inline now actually inlines instead of crashing
    the compiler or producing corrupt object files. A helper like
    cStart declared `assembler; nostackframe; inline;` in one unit
    and called from another now splices into the caller -- no more
    `Page Fault at eip=0` / EAccessViolation when compiling
    dev/video, no more `Undefined symbol: <garbled>` from the
    linker. Same-unit asm-inline is unchanged.

  * Version bump 3.3.9c -> 3.4.0 (and IDE 1.0.23c -> 1.0.24). The
    asm-inline fix changes the .ppu format, so the new compiler
    cannot load older .ppu files. Units now land under
    `X:\fpc\units\340\` (the old `X:\fpc\units\339\` tree stays
    intact for any 3.3.9-stamped install you still want to use).


== IDE 1.0.23c / Compiler 3.3.9c ==

  * `%if` inside `asm` blocks of `specialize-set` procedures.
    Conditional asm gated on a specialize-set parameter now folds
    correctly per specialisation:

        procedure yog_to_16_mmx(page: tYOG420; yofs: integer = 0;
                                use_dither: boolean specialize [true, false]);
        begin
          asm
            ...
            %if use_dither
              paddusb mm4, dither8[eax*8]
              paddusb mm5, dither4[eax*8]
              paddusb mm6, dither8[eax*8]
            %endif
            ...
          end;
        end;

    Two specialised copies are emitted -- one with the conditional
    block spliced in, one without -- and the dispatch stub folds
    constant call sites to a direct call into the matching wrapper.

  * Asm const-expression evaluator handles untyped ordinal constants.
    `%if` (and `db`, `dw`, etc.) accepts an in-scope `const k = N;`
    or `const k = TRUE;` reference and inlines the integer value.
    Boolean/char/enum/integer constants all work; the previous
    behaviour was "wrong sym type" for any non-staticvar const.

  * Wrapper procs synthesised by specialize-set inherit the source
    proc's `inline;' directive instead of being unconditionally
    marked inline. Asm-bodied wrappers (and any other body that
    triggers `pio_inline_not_possible') now stay regular calls,
    avoiding spurious notes -- the dispatch stub is still inline,
    so constant call sites continue to fold to a direct call.


== IDE 1.0.23b / Compiler 3.3.9b ==

  * `codegen-proc` parameter modifier (v5). A parameter declared
    `codegen` lets the body of the proc emit a single inline-asm
    template that the compiler patches per call site with the
    actual operand of that argument. Both immediate and pointer
    operands are supported, including memory-displacement patch
    sites (e.g. `mov eax, [ebx + arg]`). One template, many
    specialised emit sites -- no per-call thunk, no register
    shuffling.

  * `assembler; nostackframe; inline;` accepts cross-register
    reads of register-cc parameters. Previously the body had to
    consume each register-cc param from the register the calling
    convention placed it in (eax/edx/ecx for the first three
    integer args). Now the body may read `arg` from a different
    register and the compiler rewrites the access at splice time.
    Lets you write the body in whatever register layout suits the
    instruction sequence rather than the cc.

  * Quieter inline diagnostics. `-vy` no longer echoes a "Not
    inlining ..." line for every call site of a proc the parser
    already rejected once (self-recursion, pio_inline_not_possible,
    missing inlining-info). Per-call-site diagnostics are now
    reserved for site-specific reasons -- SCC defer, budget
    exceeded, hidden-symbol cross-unit, unsafe param construct.


== IDE 1.0.23a / Compiler 3.3.9a ==

  * New `specialize-set` parameter modifier. When a parameter
    only ever takes a few known constant values, you can list
    them and the compiler will generate a fast specialised
    path for each:

        procedure f(a: integer; k: integer specialize [1, 4, 8]);
        begin
          writeln(a + k * 100);
        end;

    Constant call sites collapse to a direct call into the
    matching specialisation; variable call sites become a small
    case-table dispatch. Set syntax accepts literals, named
    consts, and ranges: [1, 4, 8], [0..3], [0, 2, 4..7]. Up to
    64 specialisations per proc; parameter type must be ordinal.

    Limitations in this first cut: no methods (class/record/
    object); only one specialize-set parameter per proc; can't
    self-recurse from inside the body; can't mix with regular
    overloads of the same name in the same scope.


== IDE 1.0.23 / Compiler 3.3.9 ==

  * Intel asm conditionals. `%if / %elseif / %else / %endif`
    now work inside Intel-syntax asm blocks, with the usual
    integer arithmetic and in-scope const references in the
    condition. AT&T asm is unchanged.

  * Inlining is more aggressive by default. The classic depth-
    decay formula has been replaced with a flat per-call-site
    budget (1000 nodes), so mid-sized helpers no longer get
    rejected just for being four calls deep. To restore the
    previous behaviour: `-OoINLINESITEBUDGET=0`.

  * Better diagnostics when an `assembler; inline;` proc is
    rejected. Instead of the bare "assembler not yet supported
    inside inline procedure", the compiler now tells you exactly
    why -- missing `nostackframe`, unsupported parameter type,
    wrong calling convention, etc.

  * Inline-tuning knobs. Four `-Oo<KEY>=N` options to tune
    inlining policy:
        -OoINLINEAUTOLIMIT=N    auto-inline gate (default 25)
        -OoINLINEHARDCAP=N      hard per-site body cap
        -OoINLINEGROWTHCAP=N    cumulative growth cap per proc
        -OoINLINESITEBUDGET=N   flat per-site budget (default 1000;
                                set 0 for the legacy depth formula)
    Use `-vy` to see why a call wasn't inlined and `-vd` to see
    auto-inline decisions.


== IDE 1.0.18 .. 1.0.22 / Compiler 3.3.4 .. 3.3.8 ==

(These features rolled in over several versions. Listed here
together because they form one coherent extension to inline
assembler.)

  * Inline assembler functions. Procedures and functions
    declared `assembler; nostackframe; inline;` are now spliced
    directly into the caller -- no `call`/`ret`, just the body's
    instructions emitted in place. This started as zero-arg
    void-return procs and grew incrementally:

      - bodies may reference globals and typed constants
      - bodies may use local labels and branch between them;
        each splice gets its own fresh set of labels so the same
        helper can be inlined many times in one routine
      - functions may return a value when the result fits in a
        single integer register (longint, dword, pointer, ...)
      - parameters may be taken in registers (the default
        `register;` cc on i386 puts the first three integer args
        in `%eax`, `%edx`, `%ecx`, and the body sees them there
        directly -- no need to name them in the body)

    Combined, these let you write things like:

        function add(a, b: longint): longint;
          register; assembler; nostackframe; inline;
        asm
          addl %edx, %eax
        end;

    and have `x := add(1, 2) + add(3, 4);` collapse to four
    inline `addl` instructions plus the loads needed by the
    caller. Stack-passed args, by-reference params (var/out/
    constref), FPU/MM-register params, and float/multi-register
    returns are still rejected by the gate.

    Treat this as a useful but lightly-tested extension. If a
    pure-asm proc that compiled fine before suddenly errors or
    produces strange code, the inliner is the first thing to
    suspect -- removing the `inline;` directive is a quick way
    to confirm.

  * `var x: T align N;` for static globals. Lets a single
    declaration request stricter alignment than the target's
    default cap -- handy for MMX/SSE scratch globals on go32v2
    that need 8/16-byte alignment without a getmem-and-align
    dance:

        var mmreg : qword align 8;
        var sse_buf : array[0..3] of single align 16;

    N must be a power of two in 1..128. Initialised vars
    (`var x: T align N = init;`) are limited to N <= 4 on
    go32v2 (DJGPP COFF object-format constraint); the compiler
    raises an error rather than silently clamping. Locals and
    parameters are not aligned (the prologue does not realign
    ESP).


== IDE 1.0.17 / Compiler 3.3.3 ==

  * Quick-Open (Ctrl+U): typing a `.` in the filter now matches
    the full basename, so files outside the editor's mask (e.g.
    `play.log`) show up as you type. Pressing Enter on an entry
    with a `.` that has no listbox match resolves the literal
    text against the project dir and every -Fu/-Fi search dir
    and opens it if found.

  * File|Open, File|Open Recent, and OpenSearch no longer open
    a second editor window when the file is already open --
    they focus the existing window instead. (File|New still
    creates a fresh untitled window.) Stops the same file
    ending up loaded twice with diverging unsaved edits.


== IDE 1.0.16 / Compiler 3.3.3 ==

IDE
  * Quick-Open (Ctrl+U): mask textbox to filter the file list
    by extension or name pattern; persists across sessions.
    Result list sorts so .pas/.pp sources show ahead of .ppu/.o
    build artefacts.
  * DOS Shell: command prompt is marked so you can tell you're
    in a shell-out; refuses to re-enter while one is already
    running -- avoids the stacked-IDE / leaked-temp-files trap.
  * Editor color fixes; new INI and ASM file syntax highlighting.
  * Run profiles: named bundles of (main file, run params),
    switchable from the Run menu. Per-project, persisted with
    the desktop.
  * Alt+Up / Alt+Down: jump between interface declaration and
    implementation of the procedure under the cursor.
  * Ctrl+Enter go-to-definition; Alt+Left / Alt+Right back/
    forward navigation history (browser-style).
  * Shift+Tab peek-definition popup -- shows the declaration of
    the symbol under the cursor without leaving your spot.
  * Find in Files: dialog state (last query, mask, options)
    persists across sessions; fixed a command-code clash that
    was triggering Comment-selection instead.
  * Search | Jump to Asm: grayed out when no source is focused.
  * Wordstar prefix chord (Ctrl-K, Ctrl-Q) no longer eats its
    second key when that key matches a menu hot-key letter
    (e.g. Ctrl-K W).
  * Help | What's new...: this dialog.
  * About box and splash banner now show "-O3" suffix when the
    binary was built with the -O3 chain.

Compiler
  * Faster symbol browsing on large projects (browcol switched
    from a sorted collection to a hash table -- the old
    O(N log N) insert dominated on big projects).


== IDE 1.0.15 / Compiler 3.3.2 ==

First version to stamp the build commit short hash into the
binary banners (e.g. "3.3.2-a885a49" / "1.0.15-a885a49").

IDE
  * Ctrl+U Quick-Open by filename across project + -Fu/-Fi paths.
  * Find in Files (Ctrl+Shift+F), results in the Messages window.
  * Search | Jump to Asm Source (Alt+A); auto-recompiles -al if
    needed.
  * Open source files maximized + optional chromeless full-screen
    mode (F5 toggles); two new flags in Options | Editor.
  * S3-specific wide text-mode probe runs after VBE enumeration
    so S3-family chipsets expose the 100/132-column modes that
    the BIOS hides.
  * Recent Files uses move-to-front MRU on every open.
  * DOS Shell / File|Open anchor to the IDE's launch directory.
  * Pentium CPU-target menu labels corrected (-CpPENTIUM2 was
    mis-labelled "PentiumMMX" -- selecting it on a real P55C
    crashed with invalid-opcode / page fault).

Compiler (i386)
  * New PENTIUMMMX cputype (P55C; P5 + MMX, no CMOV) between
    Pentium and Pentium 2.
  * -CpPENTIUM4 and friends now auto-define CPUX86_HAS_MMX /
    _SSEUNIT / _SSE2 to match the selected cputype -- no manual
    -d flags needed.
  * Faster integer multiply by 2^n +/- 1 (peephole now lowers
    these to lea/shl + add/sub).

RTL (i386 / go32v2)
  * MMX FillChar / FillWord / FillDWord / FillQWord variants,
    auto-dispatched on MMX-capable CPUs without SSE2.
  * Move: startup probe detects broken 64-bit-precision emulator
    FPUs (em-dosbox, 86Box default) and falls back to a plain
    rep-movsl path that avoids x87 entirely.
  * Text-mode cursor scales to the actual VGA font height
    (16 scan lines in 80x25) instead of a hardcoded 7.
